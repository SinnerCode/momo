# Momo build tooling

Everything Momo adds lives in `i18n/` and `.github/`. No upstream Peach file is edited, so upstream merges do not conflict.

| File | Role |
| --- | --- |
| `ts.mjs` | Finds Chinese strings in `frontend/src` and `web/index.html` (oxc-parser AST); rewrites them at build time |
| `py.py` | Same for `src/peach` and the amane bridge (Python `ast`); also swaps the favicon |
| `translate.py` | Fills `en.json` through DeepL; sends only strings it has not seen |
| `en.json` | Catalog: Chinese source → English |
| `manual.json` | Hand translations for strings DeepL cannot keep intact; they win over DeepL |
| `allow.txt` | UI words to translate even though the backend uses them as data (optionally limited to files) |
| `glossary.tsv` | DeepL glossary for library terms (番号 → video code, 厂牌 → studio…) |
| `backend-strings.json` | Generated by `translate.py`; tells `ts.mjs` which frontend strings the backend also uses |
| `brand/` | Momo logo and icon, installed under Peach's file names |
| `Dockerfile` | Official Peach image + translated Python + rebuilt translated frontend + Momo icon |

## Translation rules

- A string in a matching position (comparisons, keys, regex, `includes`, Set/Map lookups, literal types) is data, and data strings stay Chinese.
- Frontend strings used only for internal state (`===`, `switch`, keys) translate at every site at once, so values and checks still agree. That only happens when the backend never uses the exact string and no site parses outside text with it.
- Each tool skips a string at every site in its language once it finds one data use. Python never translates a string Python matches.
- The standalone word "Peach" becomes "Momo" in displayed text. `peach-*`, `Peach.app`, `X-Peach-*`, the `peach` CLI and env vars stay.

## Update to a new Peach release

```sh
git fetch upstream --tags
git merge v0.53.0                       # the release tag
python3 -I i18n/translate.py            # DeepL key in ~/.secrets/deepl-api-key; only new strings are sent
```

1. Fix anything listed in `i18n/failed.json` by adding it to `manual.json`, then run `translate.py` again.
2. Set `BASE` in `i18n/Dockerfile` to the official image of that release: `longmeidao/peach:<version>@<digest>`.
3. Check the translated tree: copy the repo, run `py.py apply` and `ts.mjs apply` on the copy, then `npm run typecheck && npm run lint` in its `frontend/`. A literal type that changed language fails typecheck. Fix it by removing the word from `allow.txt`.
4. Build: `docker buildx build -f i18n/Dockerfile -t ghcr.io/nael-nathanael/momo:<version> .`

To change how one word is translated, edit `glossary.tsv`, then run `python3 -I i18n/translate.py --retranslate <word>`.
